# 考试通主动备考助手（1.3 测试版）

## 当前已经实现

入口位于首页“让助手帮我备考”、考试档案工具按钮，以及考试库无结果时的“让助手联网查这个考试”。没有收录的考试可直接输入，不要求先建档。

输入考试正式名称、地区、现有基础与薄弱点、资料偏好、个人复习截止日、学习日及每天时间。启动一次研究后，后台实际调用 Codex 的 live web_search：查主办方、报名通知、大纲和样题，再寻找匹配题库。客户端显示真实检索次数，可停止或断线后重新连接继续查看，不用把资料预先塞入本地目录。

研究结果包含原始 HTTPS 来源、适用版本、未核实事项和题库候选的匹配理由、费用、局限与导入条件。所有结果均标记为 AI 检索整理、需核对原文；类型“官方”是 AI 判断，不能当成平台背书。没有搜索工具完成事件就拒绝返回“联网完成”。检索次数是工具完成次数，不等于网页数，也不是事实核验保证。来源链接和结论仍可能出错。

从今天至个人截止日前一天，按选定学习日、每日预算，分配基础理解、专项练习、模拟及错题复盘。AI 提供基于大纲和基础的科目及学习重点；日期、阶段、每日时长由程序排定。计划和打卡保存到本地 SQLite；“从今天重新安排未完成任务”只移动未完成项、保留已完成记录、保持任务次序并遵守预算。放不下的任务进入“待安排”，不会偷偷超时或删除。此操作不消耗模型调用。

题库可打开原页，或复制带来源和导入条件的候选资料，再打开掌心刷题。当前没有跨应用登录、自动下载题库、共享进度或直接导入的接口。复制的链接不冒充题库文件。购买及导入由用户核实后完成。

## 真实实测与自动测试的界限

2026-11-14 在本项目环境中通过实际 Codex 登录执行了一次“全国计算机等级考试二级 Python / 上海 / 2027-03-01 / 每日45分钟”研究，观察到4次 web_search 工具完成事件，输出8个来源、3个题库候选。检索结果明确表示未核实2027年上海安排。研究 JSON 保存在测试夹具中，标注为实测 AI 输出，并非人工逐项核验。

测试夹具只供 Flutter 页面渲染和复现，应用运行时不会加载它作为实时结果。其他异步、失败及打卡测试使用明确标注的固定数据，不代表真实搜索。最终安装包仍须连接已经部署的备考服务；仓库中不预置虚构服务地址或个人访问码。

## 服务部署

服务仅依赖 Node.js >=22 的标准库，无 npm 第三方依赖、无模型常驻进程。空闲时只有一个轻量 HTTP 服务；每次研究启动一个临时 Codex 进程，最多240秒，结束或取消后回收。单服务同一时间只允许一个研究，每个访问码每小时最多6次。现有 Codex 的模型配置默认保留，可用 EXAMHUB_MODEL 显式选择已支持的模型。没有读取或复制掌心刷题私有源代码、账户或题库到本仓库。

1. 准备运行身份及其现有 Codex 登录，确认 `codex exec` 能够使用 live web_search。不要把 Codex 登录令牌当作客户端访问码。
2. 部署 server/ 至 /opt/examhub/server，运行 `node --test /opt/examhub/server/test/*.test.mjs`。
3. 将 deploy/assistant.env.example 复制到仓库外 /etc/examhub/assistant.env，权限0600，服务身份可读。使用 `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` 为每位使用者分别生成随机访问码，设置 EXAMHUB_ACCESS_TOKENS 为 JSON 字符串数组。不通过 GitHub 传递这些值。
4. 依据实际服务身份修改 systemd 示例中的 User、Node 和 Codex 路径。沿用该身份已获授权的 Codex 环境，不复制其他项目密钥。配置文件示例不是一键部署脚本，未自动修改任何生产服务。
5. 将 nginx 片段加入现有 HTTPS 站点并检查配置。访问 /examhub-assistant/v1/health 必须携带个人访问码；未认证应返回401，正确访问返回服务名称。HTTP不用于App连接。
6. 在 App 备考助手右上角“连接备考服务”填写 HTTPS 基址（例如站点下 /examhub-assistant）和自己的访问码。地址可本地保存，访问码仅留在当前进程；重启后须重新填写。APK不包含服务端凭据。
7. 通过正式域名发起一次真实研究，确认来源可打开、停止按钮有效、计划打卡与重开恢复正常，再向使用者开放。

临时任务与结果只在服务内存中存留，完成后最长1小时；重启服务会清空任务。App取得结果后保存于设备，可离线查看。服务启动参数含凭据时不要复制命令到工单；示例通过受限环境文件注入。迁移设备或卸载会丢失本地计划，目前没有云端同步。

## 接口

所有路由要求 `Authorization: Bearer <个人访问码>`。多个码在服务端隔离任务；不是公开无认证的 AI 接口。

- GET /v1/health：验证服务连接。
- POST /v1/research：JSON含exam、region、level、preferences、targetDate、minutes、studyDays，返回202及任务id。默认学习日1..7，1为周一；日期为中国当日之后1至730天，每日15至480分钟。
- GET /v1/research/:id：轮询running/completed/failed/cancelled与进度。完成时含result和plan。
- DELETE /v1/research/:id：中止自己的研究。

请求体上限8KiB，单次输出上限4MiB；无跨域开放配置。数据和凭据不写入服务访问日志。生产反向代理也应避免记录请求体与Authorization。

## 后续开发顺序

1. 部署并进行手机真实联网验收，减少连接配置操作（接入现有账户体系）。
2. 与掌心刷题协商双向身份认证和题库元数据搜索，按考试、大纲、版本匹配已有个人题库，授权后交接文件导入。
3. 接回练习正确率、耗时和错题标签，使薄弱点诊断、任务权重与复习间隔随真实练习结果调整。
4. 加入用户可控的定时复查和通知，只在官方公告、时间或资料发生变化时提示；尚未实现无人值守定时搜索、推送和跨设备同步。

当前不是完整学习路径优化器：学习重点由AI建议，排程用可解释规则，尚不能证明全部复习任务足以达到通过线。重新“检索资料并规划复习”会替换该入口当前计划；打卡不会自动迁入新计划。只补排时间时使用本地重新安排按钮。

## 调用依据

采用官方 [Codex 非交互模式文档](https://learn.chatgpt.com/docs/non-interactive-mode) 的 JSONL、临时执行与结构化输出，以及[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)的 live web_search、禁用 shell。没有为 App 申请新 API 密钥、替换服务器默认模型或更改掌心刷题生产后端。
