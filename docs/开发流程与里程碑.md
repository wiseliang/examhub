# 考试通开发流程与里程碑

更新日期：2026-11-14

## 开发基线

继续现有 Flutter 项目，首个验收平台为 Android。目标用户暂沿用原设计的应届毕业生至职场人群。当前用户授权为安排开发并开始；以下为执行基线，用户后续可调整优先级。

长期定位保留“考试信息 + 社区”，下一版先交付可更新的信息工具。现有 40 个考试仅作为目录与演示数据，不代表报名条件和时间已完成官方核验。

## 迭代顺序和验收

| 里程碑 | 工作范围 | 验收标准 | 当前状态 |
| --- | --- | --- | --- |
| M0 工程恢复 | 开发环境、依赖锁定、数据读写修复、实际业务测试、CI | 静态检查和业务测试通过；构建与真机结果分别记录 | 进行中 |
| M1 数据基础 | 考试档案、年度/地区/批次安排、公告与来源、数据库迁移 | 同一考试可存多省多批次；历史关注不丢失；预计信息与正式公告可区分 | 待开始 |
| M2 更新服务 | FastAPI、管理入口、草稿/核验/发布流程、客户端增量更新 | 后台发布后 App 获取更新；抓取或解析失败不覆盖已发布数据；离线可读 | 待开始 |
| M3 用户流程 | 搜索筛选、公告原文、关注、日历、提醒开关和提前时间 | 找考试→查条件/安排→关注→查看日历→接收提醒可走通 | 待开始 |
| M4 小范围试用 | 重点考试核验、Android 打包安装、异常与更新测试 | 提供可安装包及已知问题清单；完成真实设备验收 | 待开始 |

不把上次讨论的粗略周数作为交付承诺。M0 完成后，根据实际构建和数据维护成本估算后续批次。

## 第一批工作包：M0

- 修复 SQLite 字段的 JSON 编解码，保留科目、标签和特殊字符。
- 修复公告关键信息解析、今天的时间节点遗漏和按天倒计时。
- 防止多个页面同时触发重复数据库初始化。
- 修复历史清空及切换到“我的”后关注列表未刷新。
- 用真实 SQLite 和实际页面流程替换默认计数器测试。
- 锁定依赖，建立格式、静态检查、测试和 Android 调试构建的 CI。
- 记录执行结果，保留尚未实现的功能清单。

## 数据规则：M1 必须先明确

1. `exam` 表示考试档案；安排按年份、地区、级别和批次独立建模。
2. 报名开始、截止、考试、出分等节点有独立状态与时区；不得把“每年某月”推算成确定日期。
3. 官方来源 URL、公告发布时间、抓取时间、核验时间分别记录。
4. AI 提取结果先为草稿，日期和条件变更经核验后发布。
5. 信息变更保留版本；取消、延期、待公布与已确认不能混用。
6. 条件匹配展示匹配依据与未确定项，不把简单标签当成最终报考资格判断。
7. 预设难度和含金量不能冒充社区评分；发布前移除、标明依据或替换为可核验信息。
8. 公告、档案、安排更新与用户关注分开存储；更新不得清除个人数据。

## 日常开发流程

1. 从当前验收点选一个工作包，写清问题、范围和验收标准。
2. 使用独立 Git 分支实现；数据库变更先写迁移和兼容方案。
3. 执行格式检查、静态分析和与改动相关的业务测试。
4. 涉及设备能力、权限、通知、安装升级时增加 Android 真机验证。
5. 更新开发记录和已知限制，形成可审查的差异和测试结果。
6. 提交审查后合并；外部发布、正式签名及服务器部署在具体方案和配置明确后执行。

## 验证命令

```sh
flutter pub get --enforce-lockfile
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test
flutter build apk --debug
```

Flutter 版本以 `.github/workflows/flutter-checks.yml` 为准。自动化测试使用临时目录里的 SQLite，不读取个人数据。CI 构建成功也不代表通过真机提醒和升级验收。
